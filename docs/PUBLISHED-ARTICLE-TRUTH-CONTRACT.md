# 微信公众号已发布文章真值合同

状态：最高优先级数据口径红线  
生效日期：2026-07-15  
适用范围：采集、归档、统计、接口状态、日志、文档、飞书多维表格同步和对外汇报

## 永久撤销的错误结论

- `freepublish/batchget.total_count=273` **不等于**公众号历史已发布 273 篇文章。
- 273 个发布对象中当前拆出的 311 条文章记录**不等于**已经核验的历史文章总量。
- 任一官方接口的分页完成、任一数据库表的行数、任一日期范围内的指标行数，都不能单独证明“历史文章全量已抓完”。

任何代码、日志、接口、卡片或文档都不得再把 `273`、`311` 或其他单源计数表述为：

- “历史全量”
- “已抓完”
- “公众号只有 X 篇”
- “X/X 篇已完成”

## 已知事实的正确命名

- `freepublish/batchget.total_count`：该接口在对应快照中的**发布对象数**。
- `official_content_objects` 行数：本地已归档的**发布对象记录数**。
- `official_content_articles` 行数：从已归档对象中拆出的**文章记录数**。
- 阅读、分享、粉丝等分析接口行数：对应接口和时间粒度下的**指标记录数**。

这些计数可以报告，但必须带上准确名称、数据源、快照时间和覆盖范围，不能改名为历史文章总量。

## “历史已发布全量已核验”的必要条件

只有同时满足以下条件，才允许把状态改为“已核验”：

1. 保存所有相关微信公众号官方 API 的原始请求、原始响应及全部可获取字段。
2. 各接口按其官方分页或时间窗口完成采集，并记录起止时间、游标、页数、调用量、错误与缺口。
3. 关联发布对象、文章明细、阅读分享指标及其他相关表；至少审计 `msgid`、`msg_data_id`、文章序号、`article_id`、文章 URL 和发布日期等稳定标识。
4. 明确一对多关系，完成跨接口去重，并输出无法关联、键冲突、重复记录和缺失字段清单。
5. 分别报告“发布对象数”“去重文章数”“有指标文章数”“无指标文章数”，不得用一个数字替代全部概念。
6. 对最早与最晚日期、连续月份、分页终点和异常空窗进行覆盖审计。
7. 审计结果经用户明确确认。

任何一项未满足，统一状态为：**历史全量未完成/未核验**。

## 飞书多维表格门禁

- 在历史全量关联、去重和覆盖审计完成并经用户确认前，飞书多维表格批量同步保持关闭。
- 本地数据库继续保存原始数据和规范化数据，不能因 Base 当前没有对应字段而丢弃信息。
- 启用 Base 同步后，应从本地数据库批量同步；不得边抓边把未经核验的单源计数包装成全量结果。

## 素材库边界

- 图片素材、图文素材、视频素材和语音素材不作为“已发布文章历史全量”的真相源，也不纳入已发布文章自动同步。
- 如为排查关联缺口而读取素材接口，只能作为辅助证据，必须单独标注来源，不能与已发布文章计数混合。

## 自动化守护

`archive/store_test.go` 中的 `TestFreePublishTotalCountIsObjectCountNotArticleCount` 固定验证：一个发布对象可以拆出多篇文章，`total_count` 只能按对象数解释，不能按文章数解释。
